## 3. 清到一半死咗點算

### 3.1 ⭐ 一個睇得到嘅終點狀態

**規矩：`quote_photos.purged_at` 只喺「R2 同 Drive 兩邊都處理完」之後先寫。**

> 物理上行唔到落去 ⇒ `purged_at` 唔會被寫 ⇒ ⭐ 留喺回收站，下次撳得返。

### 3.2 再試得

**設定頁最底「診斷資料」加一行**（同 PR #19「清掉傳唔到嘅相」擺埋一齊）：

> **有 N 張相刪咗一半**（雲端未清乾淨）。撳一下繼續清。

⛔ **N 係零就成行唔出**（同 PR #19 同一條規矩）。
⭐ 撳落去就係再叫一次 `/purge`，**由頭數起**（已經清咗嘅會回 `skip`）。

### 3.3 ⛔ 分批，而且撞到上限一定要講

tree app 個 `PURGE_BATCH_MAX = { project: 10, tree: 6, photo: 6 }` ——
**⛔ 呢個唔係品味，係 Cloudflare 每個 request 50 個 subrequest 嘅上限除以每張相嘅成本**，
而且係「睇住一次真跑喺邊界死咗（要 20 張、清咗 11 張、9 張失敗）」度出嚟嘅。

⭐ quote app 每張相平：`R2 DELETE` ＋ `driveFileExists` ＋ `trashFile` ＋ `PATCH quote_photos` ＝ **4**，
加 setup 約 4 ⇒ `floor((50 - 4) / 4) = 11` ⇒ **取 10，留鬆動**。
⚠️ 呢個數要**喺真嘢上面量返一次**先定死，⛔ 唔准照抄 tree app 就算。

**loop 一定要有上限**（tree app 用 20 批），而且撞到上限要回一個
**`hitLimit: true`**，⛔ **唔准靜靜雞當做完** —— tree app 個
`HardDeleteResult` 就係專登有呢個欄。
