# 現場影相流程 —— 三個做法俾你揀

出稿：2026-08-23　　任務：quote app 現場流程（唔屬於 P3c）

---

## 結論

**推薦乙：照 tree app 重排改樹版，再喺樹木清單加一個相機掣。**
四樣你話煩嘅嘢全部解決，而且同 tree app 一樣，阿耀唔使學兩套。

---

## 一、現況實測（唔係我估）

我入咗個 preview 度量：

- 改樹嗰版要**碌 2433px，畫面得 1232px** —— 即係**兩版**。
- 第一個「拍攝」掣喺 **1559px** 位置 —— 要碌超過一整版先見到。
- 而嗰棵樹**淨係剔咗一個工序**。剔三個會再長一大截。

行去影一張相要：首頁 → 工程 → 樹木清單 → 揀樹 → **碌兩版** → 拍攝。

**你揀嘅四樣煩處：** 碌太耐、撳太多次、剔工序唔順、影完要揾返落邊格。

⛔ **D7 嗰條係我揀錯。** 當時我揀「全部擺喺改樹版、碌落去」，理由係「戴住手套，少撳一次好過少碌一下」。真機證明兩樣都差。

## 二、tree app 點做（出處：`tree-app-v7/src/ui/screens.tsx`）

`TreeDetailScreen` 由上到下嘅次序係：

```
TreeSummaryRow → WholeViewSection → PruningItemsSection → CloseUpItemsSection → EnvironmentSection
```

三件事值得抄：

1. **相片喺最上面。** 樹嘅資料淨係一行摘要（`TreeSummaryRow`），⛔ 唔係一堆輸入格。
2. **揀類別用彈出式 picker**（`CategoryPickerModal`），⛔ 唔係一列剔掣霸住成版。
3. 工序相按類別分組排，同 PDF 次序一致。

quote app 而家啱啱相反：輸入格喺上、剔掣霸半版、相喺最底。

---

## 三、三個做法

### 甲　照 tree app 重排改樹版

- 樹資料（品種、樹高、DBH、冠幅）收成**一行摘要**，撳一下先展開輸入
- 揀工序改用**彈出式 picker**，唔再一列剔掣
- **相片擺最上面**

解決：碌太耐 ✅　剔工序唔順 ✅　影完揾返落邊格 ✅　撳太多次 ❌（唔變）
改動：改樹版重排 ＋ 一個新 picker。中等。

### 乙　甲 ＋ 樹木清單直接開相機　⭐ 推薦

喺樹木清單每張樹卡加一個相機掣，撳落去直接入嗰棵樹嘅相片位。

解決：**四樣全部** ✅
改動：甲 再加樹木清單一個掣。大少少。
⭐ 完全跟足 tree app 嘅結構，兩個 app 用法一致。

### 丙　另開一個「影相版」

改樹版維持原狀，另開一版淨係得相格。

解決：碌 ✅　撳 ✅　揾格 ✅　剔工序 ⚠️（要喺兩個版都改得到）
⛔ 後果：同 tree app 唔一樣，阿耀要學兩套；工序可以喺兩個地方改，容易出現「究竟喺邊度改咗」嘅唔一致。
⚠️ 我唔建議。

---

## 四、點解推薦乙

1. **四樣煩處一次過解決**，唔使做完再返轉頭。
2. **跟足 tree app**，唔使發明新嘢。阿耀兩個 app 用同一套手勢。
3. ⛔ **唔掂上載、派號、Drive 任何一條路** —— 純畫面重排，risk 低。
4. 唔會新增一個獨立畫面，資料唔會有兩個入口。

---

## 五、點解要行喺 P3c-2 之前

P3c-2 係「取消工序 / 改工序 → 重新編號 ＋ Drive 改名」。
嗰啲動作嘅**入口就係揀工序個 UI**。如果而家先做 P3c-2、之後再改 UI，就要**做兩次**。
所以次序：**P3c-1 驗收 → 流程重排 → P3c-2**。
