## 三、同 Tree app 嘅關係

- **兩個 app 分開，唔合併。** 中標之後轉工程（P6）仍然係跨 app 嘅動作。
- **只抄結構同畫面**（波浪頭、浮卡、底部導航、卡片、chips、Build ID 格式），
  令同事開兩個 app 都係同一種手感，唔使學兩套。
- **唯一真正共用嘅嘢係 Supabase**（同一個 project）。所以呢度最危險。
- **只准掂 `quote_` 開頭嘅表**同 `quote` / `is_quote_` 開頭嘅 function。
  `projects`、`photos`、`admins` 係 tree app 嘅，唔准 alter、唔准 drop、唔准加 trigger、
  唔准改 RLS 或者 GRANT，連 update 一行都唔准。
- **讀 `tree-app-v7` 只可以讀。** 參考用嘅 clone 要即刻 `git remote remove origin`，
  令 push 物理上做唔到。今次讀嘅係 `feature/slice2`（`888956b`，version 8.0.0）。
- admin 判斷用 **`quote_admins` + `is_quote_admin()`**，唔係 tree app 個 `admins` 表。
  抄 code 嗰陣好易接錯表，呢個係真·危險位。

## 五、現場表單規格

### 5.1 新增工程（`quote_records`）

欄位順序（P2.5 起）：

```
日期（預設今日）→ 日／夜工作（預設日更）→ 工程名稱 → 地址 → 地區
→ 客戶 → 聯絡人 → 電話 → 其他備註
```

- **必填三個**：工程名稱、地址、地區。未填就喺欄位下面出中文提示，**唔會送去 DB**。
- **拿走咗三個**：預計開工、Odoo REF#、大判。
  客戶就係大判（Jason 確認），碧瑤、新輝呢啲直接填落客戶。
- ⛔ **舊單欄位唔准刪**：`main_con`、`site`、`start_time`、`odoo_ref` 唔再顯示，
  但欄位仲喺 DB、舊單資料要永遠查得返。做法係**呢幾個 key 完全唔出現喺 payload** ——
  唔喺 payload 出現，`update` 就唔會郁佢哋。照送空字串就等於每次開返舊單再儲存都靜靜刪一次。

### 5.2 GPS 同十八區

- 地址欄旁邊有「用 GPS 定位」掣。撳咗攞座標存 `gps_lat`/`gps_lng`/`gps_at`，
  再用 Nominatim 反查文字地址填入地址欄，順便由區名判斷地區。
- `address_source` / `region_source` 係 `gps` 嗰陣，欄位下面出「由 GPS 自動填，請確認」；
  用家一改嗰個欄，來源即刻變返 `manual`。
- **十八區對應（硬對應，唔准估）**：
  - `HK`：中西區、灣仔區、東區、南區、**離島區**
  - `KLN`：油尖旺區、深水埗區、九龍城區、黃大仙區、觀塘區
  - `NT`：葵青區、荃灣區、屯門區、元朗區、北區、大埔區、沙田區、西貢區
  - **離島算 HK**：單價表「香港／大嶼山」係同一個價，大嶼山喺離島區。
  - 中英文都要對到（Nominatim 有時出英文有時出中文）。
  - ⛔ **整格比對，唔做「包含」比對**：「North Point」喺東區(HK)，
    用包含就會誤中「North」＝北區(NT)，夾車同吊機價即刻報錯。
    **認唔到就留返地區未揀 + 出「認唔到地區，請自己揀」，寧願認唔到都唔可以認錯。**
- **Nominatim 使用守則**：只可以喺撳掣嗰陣發**一次**請求；唔准 debounce 跟住打字自動查、
  唔准 autocomplete、唔准連環快發；同一組座標唔重複查（記住上次結果）。
  地址欄附近要長期顯示「地址資料來自 OpenStreetMap」做出處標示（佢哋條款要求）。
- **失敗處理（地盤成日冇訊號）**：唔准權限、攞唔到定位、反查出錯、冇網，
  **全部出清楚中文一句**，而且地址欄照樣打得字、**全程唔准 block 儲存**。
  座標攞到但反查失敗，**一定要照存座標**，唔好連座標都掉咗。

⛔ **總規則：全部任揀，冇任何互斥，冇自動熄掣。**

**App 只負責如實記錄現場，唔做判斷、唔幫人糾正。**

3. **機械（選填）**：
   - 吊雞：`crane_fatboy` 肥仔-30噸、`crane_fai30` 輝哥-30噸+科同、

   - `none` 不用
   - ⚠️ **肥仔就係東哥，同一個人，app 一律顯示「肥仔」。**
4. **起樹頭（任揀）**：`yes_self` 自己起、`yes_chuen` 銓哥報價、`no` 不要。三個獨立。

### 5.6 型別規矩（全部表通用）

- 文字欄 `not null default ''` → 空白**送空字串，永遠唔送 null**

- 陣列欄 → 就算乜都冇揀都要送 `[]`

## 九、相片點存（P3，未開工）

⚠️ **Jason 2026-08-14 更正咗一個好重要嘅講法**，開 P3 之前一定要睇。

### 三個地方各自係乜

| 地方 | 角色 |
| --- | --- |
| **Google Drive** | **檔案庫，原圖權威** |
| **R2** | **熱儲存** —— app 唯一即時讀寫嘅**壓縮副本** |
| **Supabase** | **只存紀錄同登入，唔存 bytes** |

**相唔會存 Supabase，只會存 R2。**

⚠️ **R2 唔係 cache，亦都唔係 master。** 正確講法係「**可重建嘅熱儲存**」。
講佢係 cache 會令人以為刪得；講佢係 master 會令人以為唔使 Drive。兩個講法都會出事。

**quote app 由第一日就 R2-only，唔使行雙寫**（tree app 嗰邊係歷史包袱）。

### 硬規矩

- ⛔ **唔准 proxy bytes，要簽 presigned URL。**
  一個 145 張相嘅工程應該係 **1 個 Worker 請求**（簽一次，出 145 條 URL），
  **唔係 145 個**。呢個係 **load-bearing 決定，唔係優化** —— 唔跟就會喺現場塞死。
- **權限**：讀 = 已登入即可；寫 = 限自己 `uid` 開頭。**零 DB 查詢。**
- **key 格式**：`uid/operation_id.jpg`
- **上傳要 readback verify**：對 `size` 同 `sha256`。
- **`operation_id` 影相嗰刻定死，每次 retry 重用** —— 唔係咁就會出重複檔。
- ⛔ **由第一日就要有刪除路徑。**
  tree app 而家欠住呢樣：2026-08-13 實測 **199 張已 purge 嘅相，198 張實物仲喺 R2，
  共 147MB；purge 引致嘅 R2 刪除次數係 0**。即係「刪咗」只係 DB 嘅事，位元一直留住。
- ⛔ **刪除次序反直覺：R2 要喺 Drive 入垃圾桶之前刪。**
  （次序反轉就會出現「Drive 已經冇咗、R2 仲有一份冇人知」嘅孤兒。）
- ⛔ **唔准靜靜降級。** 攞唔到相要有**具名狀態行到 UI**，唔可以靜靜顯示空白。

## 附錄 A：事故紀錄

**I1（08-13，P1 上線後）`permission denied for table quote_records`**
根因：P1 張 SQL 開齊咗 RLS policy 但**漏咗 GRANT**，唔關前端事。
Jason 補跑 grant 就好。教訓：GRANT 決定「入唔入到張表」，RLS 決定「入到之後睇到邊幾行」，
**兩樣要齊**。

**I2（08-13，P1 blocker）空欄位撞 not-null**
現象：填漏「預計開工」／「Odoo REF#」／「內部備註」就落唔到單，
而且 DB **逐個欄**嗌，要一個一個試先知爭邊個。
根因：`inputToRow()` 將空白轉 `null`，但 schema 係 `not null default ''`。
修法：喺**資料層一個位**改晒（唔准喺個別欄位散修），加 regression test
「所有選填欄留空嘅 payload 冇任何 null」。

**I3（08-13）地區／日夜更留「未選」**
同 I2 一條根，但**唔可以用悄悄 default 修** —— 呢兩樣影響夾車、吊機、夜更價，
靜靜幫人揀等於靜靜報錯價。改成必填 + 中文提示 + call DB 之前攔住。

**I4（08-13）DB error 原文英文彈俾用家睇**
阿耀、聰、Isaac 睇唔明。加咗 `translateDbError()`：not-null 指名中文欄名、
`permission denied` 譯成「未 GRANT，要 admin 補返」、RLS 譯成權限問題、
唔識嘅出「請截圖搵 Jason」。英文原文照樣入 `console.error`。

## 附錄 B：點驗證

### 本機 harness

sandbox 冇 Supabase key（真值只喺 Cloudflare），所以每個階段都係用
**in-memory 假資料層 + Playwright** 行真流程：

- 假 api 實作返 `RecordsApi` / `TreesApi` / `SiteFormApi` 三個介面，用 `localStorage` 做 store，
  所以 reload 之後真係要重新讀，唔係靠 React state 呃自己。
- 假 DB **學返真 schema 拒收 null**，收到就照 Postgres 字眼 throw，
  咁先證到「送空字串」真係修好咗。
- `update` 只 merge 送嚟嘅 key —— 同真 DB 一樣，所以驗得到「唔會整走舊欄位」。
- harness 兩個檔（`harness.html` + `src/harness.tsx`）**每次驗完即刻刪，唔會 commit**。

UI 驗得到嘅前提係：**畫面只認 `QuoteApi` 呢個介面，唔直接摸 Supabase client。
呢個設計唔好拆走。**

### 已知陷阱

- **headless Chromium 唔會「拒絕」定位**：唔 grant 權限嗰陣佢係**永遠唔 callback**，
  唔係 `PERMISSION_DENIED`。所以要喺 `navigator.geolocation` 邊界扮 code 1，
  真機撳「封鎖」嗰下仍然要人手試（見 §12 第 2 項）。
- **sandbox 出唔到外網**：`sylvan-quote.pages.dev`、`api.cloudflare.com`、Nominatim
  全部被 egress policy 擋（CONNECT 403）。所以**線上 Build ID 同真 DB round-trip
  一定要人手驗**，反查係用 mock response 驗。
- **`todayIso()` 唔可以用 `toISOString()`**：香港朝早開單會爭返轉頭一日。
  測試亦唔可以用帶時區嘅字串建構 Date，否則會跟住跑測試嗰部機嘅時區飄。

### P2.6 換皮嗰次

45 項全過（外殼 4、基本資料 6、篩選 5、GPS 8、樹木 7、現場表 7、封存刪除登出 5），
